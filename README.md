# Workboard

Requires Node.js 22.22.1. No application dependencies or installation steps.

```sh
npm start
```

The HTTP server binds to `0.0.0.0`. `PORT` defaults to `8080`; `DB_PATH` defaults to `data/workboard.sqlite`. Parent directories are created automatically. Keep the configured SQLite file to preserve projects, project priority defaults, tasks, priorities, due dates, completion state, and archive state across restarts. Existing databases are upgraded automatically without losing data.

```sh
PORT=8080 DB_PATH=/tmp/workboard.sqlite npm start
npm test
```

Open `/` to create and open projects. The Project filter initially shows Active; switch to Archived to open or restore archived projects. Rows summarize all tasks as completed/total counts. Archiving preserves tasks but prevents task creation and completion changes, including through the API. Active project pages also support renaming with New project name and Rename project. Names are trimmed and required; renaming preserves the project URL, creation order, tasks, and summaries. Archived projects cannot be renamed until restored. Each project page supports task creation, completion checkboxes, and All/Open/Completed filtering. Each task row supports New task title and Rename task: titles are trimmed and required, while ownership, creation order, completion, and summaries stay unchanged. Archived projects disable task renaming until restored. Each task has a Task priority selector with Low, Normal, and High options. Existing tasks default to Normal on migration. Each project has a saved Default task priority selector (Low/Normal/High), initially Normal. New tasks inherit that project's current default; changing it never changes existing tasks, summaries, or either task filter. Defaults are independent across projects and survive renaming, restarts, archival, and restoration. Archived projects display the saved default but disable editing until restored. Priority changes persist independently and preserve task identity, title, completion, order, and summaries; renaming preserves priority. Archived projects disable priority edits until restored. Task filter (All/Open/Completed) and Priority filter (All/Low/Normal/High) initially show All and work together, retaining creation order. Changing either filter or editing a task preserves both selections; completion and priority edits immediately update matching rows. Renaming preserves filter membership. Both filters remain usable on archived projects, never change stored tasks, and leave summaries counting all tasks. `GET /health` returns `{"status":"ok"}`.

Each task row has a Task due date textbox and Save due date button. Dates are optional: blank input clears the saved date; otherwise only real Gregorian dates in `YYYY-MM-DD` format (years 0001–9999) are accepted after trimming. Dates are calendar days with no timezone conversion. Invalid dates leave saved data unchanged and display an alert. Saving dates preserves task identity, completion, priority, both filters, and summaries. Archived projects disable both due-date controls until restored.

Project pages also have Due from and Due through textboxes and Apply due range. Applying trimmed, valid calendar dates filters inclusively and intersects both selected task filters. Blank boundaries are unbounded; undated tasks match only when both boundaries are blank. Invalid or reversed ranges display an alert and leave the applied range unchanged. Filters are view-only, remain usable in archived projects, and reset when reopening a project. Task date, completion, and priority edits immediately re-evaluate membership without resetting the range or comboboxes.

Each task row has Destination project and Move task controls. Destinations are other active projects in creation order, using their current names; controls are disabled for archived sources or when no destinations exist. Moving to a project for the first time appends the task after all positions established there, including positions reserved for tasks currently elsewhere. Returning to a previous project restores the task's remembered position relative to other tasks, even when multiple tasks return in a different order. Moves preserve current identity, title, completion, priority, and optional due date; returning never restores older field values. The source remains open with all filters unchanged. Both summaries reflect current ownership. Persistent task/project position reservations survive restarts, project renaming, archival, and restoration. Existing databases retain their current task order on upgrade; earlier movement history unavailable in those databases cannot be reconstructed. Position reservations and ownership changes are saved together in SQLite transactions. The API uses `POST /api/projects/:projectId/tasks/:taskId/move` with a numeric `destination_project_id`, rejecting same-project, missing, or archived destinations and archived sources.

Project search and Search projects apply a literal substring query to project names, intersecting the Active/Archived filter. Task search and Search tasks apply the same rules to task titles, intersecting completion, priority, and applied due-range filters. Search trims only surrounding query whitespace and ignores only ASCII letter case; internal whitespace remains significant. Blank queries match all rows allowed by the other filters. Queries are view-only and reset on opening the list or a project. Changing other filters retains the applied query. Task edits, renaming, creation, and movement immediately re-evaluate membership without resetting the query or other filters. Search remains enabled in archived projects; existing editing restrictions and all-task summaries remain unchanged.
