# Workboard

Requires Node.js 22.22.1. No external dependencies or installation needed.

```sh
PORT=8080 DB_PATH=./data/workboard.sqlite npm start
```

The server binds to `0.0.0.0`. Defaults: port `8080`, database `data/workboard.sqlite`. Keep the configured SQLite file to preserve projects, tasks, completion state, and archive state across restarts. Existing databases are migrated automatically.

Open `/` to create and open projects, view completion summaries, and filter Active or Archived projects. Archive or restore projects from their rows. Each active project page lets you rename the project, create and rename tasks, toggle completion, set each task's priority to Low, Normal, or High, and combine the Task filter (All, Open, Completed, or Deleted) with the Priority filter (All, Low, Normal, or High). Both selections remain unchanged through task edits; visible rows immediately match both filters in creation order, while summaries always count all live tasks. Each project's Default task priority starts at Normal and can be set to Low, Normal, or High. New tasks inherit that project's saved default; changing it leaves existing tasks and both filters unchanged. Defaults and task priorities persist independently through renaming and restarts. Project renaming preserves the project URL, creation order, and tasks. Task renaming trims the title and preserves ownership, creation order, completion, and summaries. Each task also has an optional Task due date textbox and Save due date button. Saving trims the value and accepts real Gregorian dates in YYYY-MM-DD format (years 0001–9999); an empty value clears it. Invalid dates show an alert without changing saved data. Dates persist independently without timezone conversion or changes to filters, summaries, or other task data. Archived project pages keep tasks visible and filterable but disable renaming, creation, completion changes, task priority edits, default priority edits, and due-date edits. Restoration preserves and re-enables the saved default. `GET /health` returns `{"status":"ok"}`.

Due from and Due through apply an inclusive calendar-date range together with completion and priority filters. Blank boundaries are unbounded; when either boundary is set, undated tasks are excluded. Invalid dates or reversed boundaries show an alert and preserve the applied range. Edits retain all applied filters and immediately re-evaluate matching tasks. The range controls remain usable while archived; reopening from the project list resets the range to empty. Filters never change saved data or all-task summaries.

Each task row provides Destination project and Move task controls. Eligible destinations are other active projects in project creation order. First-time arrivals append after all positions established in the destination; returning tasks recover their remembered position in that project, even when returning in a different order. Movement preserves identity, current title, completion, priority and due date; the source stays open with all filters retained. Both summaries update. Move controls are disabled while archived or when there are no eligible destinations. Saved task order, per-project remembered positions, and ownership persist across restarts. Migration preserves existing task order; renaming and archive/restore preserve remembered positions.

Project search and Search projects apply a trimmed substring query to project names, intersecting the Active/Archived filter. Task search and Search tasks apply the same matching to titles, intersecting completion, priority, and due-range filters. Matching ignores ASCII letter case and treats each run of ASCII spaces and horizontal tabs as one space in both queries and names/titles. Stored and displayed text is unchanged; other internal whitespace remains significant. Queries and all other applied filters remain selected through edits, with matching rows immediately re-evaluated. Search works in archived projects and never changes saved data or summaries. Opening a project from the list resets its query; opening the list or returning through Projects resets project search.

Every task row also has a multiline Task notes textarea and Save notes button. Notes start empty and save exactly as entered, including whitespace, line breaks, Unicode, and literal markup; empty text clears them. Notes are displayed as plain text, remain independent of title-only search, and retain all applied filters when saved. They persist through edits, moves, remembered return positions, and restarts. Archived projects show saved notes with both controls disabled; restoration enables editing again. Upgrades initialize only the new notes field without altering existing task data.

Live task rows provide Delete task. Deletion retains every saved field, ownership, and remembered position but removes the task from All/Open/Completed and completion summaries. Deleted shows only deleted tasks, intersecting priority, due range, and title search; their editing and move controls are read-only. Restore task returns a task to its reserved position with all fields unchanged, even after default changes or newer task creation. Both actions retain applied filters. Archived projects disable deletion and restoration but allow reading and filtering deleted tasks. Deletion persists through restarts; upgrades initialize existing tasks as live.

```sh
npm test
node --check server.js
```

Deletion checks cover live-data migration, filter intersections and retention, read-only enforcement, live-only summaries, field preservation, reserved restoration order, default changes, archives, movement, and restart persistence.

Tests use temporary SQLite databases and verify validation, creation order, escaping, navigation markup, health, project isolation, task filters, completion changes, archive/restore, read-only enforcement, completion summaries, database migration, project and task renaming without changing identity or task state, persistent independent task priorities (including migration and archived read-only enforcement), combined priority/completion filters, selection retention and row re-evaluation after edits, project default priority migration, independent defaults and new-task inheritance without changing existing tasks or filters, optional due-date migration, Gregorian validation including leap years and year boundaries, clearing, task isolation, archived read-only enforcement, and persistence across process restarts. Due-range checks cover inclusive and one-sided bounds, undated tasks, combined filters, invalid applications preserving membership, filter retention through edits, archived filtering, and empty ranges on reopening. Move checks cover destination eligibility and names, absent destinations, first-arrival append order, reverse-order returns, reserved departed positions, ordering migration, repeated moves, source filter retention, summaries, archived enforcement, blank dates, current data preservation and restart persistence. Notes checks cover pre-notes migration, exact text and safe markup rendering, empty and whitespace-only saves, filter retention, title-only search, task isolation, movement and return order, archive enforcement, unchanged task fields and summaries, and restart persistence. Search checks cover ASCII-only folding, whitespace handling, combined filters, form state retention, row re-evaluation through edits and moves, archived searching, navigation resets, summaries, and restart persistence.
