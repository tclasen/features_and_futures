# Workboard

Requires Node.js 22.22.1. No dependency installation is needed.

```sh
PORT=8080 DB_PATH=./data/workboard.sqlite npm start
```

Open `http://localhost:8080`. `PORT` defaults to `8080`; `DB_PATH` defaults to `data/workboard.sqlite`. The server binds to `0.0.0.0`. Keep the database file to preserve projects, archive state, tasks, and completion state across restarts. Existing databases are migrated automatically. Parent directories are created automatically.

Create projects on the home page, then open a project to create tasks and toggle completion. Use New project name and Rename project to rename an active project. Names are trimmed and required; renaming preserves the URL, creation order, tasks, and completion summary and persists across restarts. The Task filter shows live tasks in All, Open, or Completed, and deleted tasks in Deleted. The Priority filter offers All, Low, Normal, and High. Both default to All on each page load; tasks matching both filters appear in creation order. Changing either filter or editing a task preserves both selections and immediately re-evaluates matching rows, without changing the project summary. Both filters remain available in archived projects.

Each task row provides New task title and Rename task. Titles are trimmed and required; renaming preserves ownership, creation order, completion, filter membership, and the project summary. Task titles persist across restarts. Each task has a Task priority selector with Low, Normal, and High options. Existing tasks default to Normal; new tasks inherit their project's saved Default task priority (initially Normal). The default selector offers Low, Normal, and High and affects only future tasks. Defaults are independent per project and persist through reloads, restarts, renaming, archival, and restoration. Changing a default leaves existing tasks and both filters unchanged. Archived projects display the saved default but disable edits until restored. Task priority edits persist independently without changing task order, title, completion, or summaries. Renaming preserves priority. Archived projects disable task renaming and priority edits until restored.

Each task row also has Task due date and Save due date controls. Save a real Gregorian date in YYYY-MM-DD format (years 0001–9999), or save an empty/whitespace-only value to clear it. Surrounding whitespace is trimmed. Invalid dates display an alert and leave the saved date unchanged. Dates are calendar days without timezone conversion, persist independently across restarts, and survive renaming, archival, and restoration. Saving a date preserves both filters and all other task data. Archived projects disable date editing until restored.

Live task rows provide Delete task; Deleted rows provide Restore task. Deletion is reversible and persists without losing any fields, ownership, or remembered positions. Deleted tasks are excluded from all live lists and completion summaries, but remain readable using Deleted intersected with priority, due range, and title search. All deleted-task editing and movement controls are disabled until restoration. Restoration recovers the reserved position before later tasks, preserves explicit priority even if the project default changed, and retains the current filters. Archived projects disable both deletion and restoration. Upgrades initialize existing tasks as live.

Each task row provides a multiline Task notes textarea and Save notes. Notes are optional plain text: saving preserves spaces, line breaks, Unicode, and literal markup without trimming; empty text clears them. Existing and new tasks start with empty notes. Notes persist across restarts, travel with moved tasks, and do not affect name/title searches, other task fields, remembered order, summaries, or selected filters. Archived projects display saved notes with both controls disabled until restoration. Database upgrades preserve existing fields while initializing notes to empty.

Each project page has Due from and Due through textboxes and Apply due range. Valid, trimmed YYYY-MM-DD boundaries are inclusive and intersect the completion and priority filters. Blank boundaries are unbounded; when either is present, undated tasks are excluded. Invalid dates or reversed boundaries show an alert and preserve the last applied range. Task edits immediately re-evaluate membership; renaming, creation, and default changes preserve all applied filters. Range controls remain usable on archived projects. Opening or reloading a project starts with empty boundaries and All in both task filters. Filtering is local to the page and never changes saved task data or all-task summaries.

Each task row has Destination project and Move task controls. Destinations list other active projects by current name in project creation order. A first-time arrival appends after all positions established in the destination, including tasks currently away. Returning tasks recover their remembered position relative to other tasks, even when they return in a different order. Each project's positions persist across restarts, renaming, archival, and restoration; existing databases retain their current task order. Moving preserves the task's current title, completion, priority, and due date rather than restoring old values or applying the destination's default. The source page stays open with all filters retained. Both project summaries reflect their current tasks, and ownership and ordering persist across restarts. Archived projects cannot send or receive tasks; move controls are disabled on archived pages or when no destinations are available.

The Project filter defaults to Active. Archive projects to move them to Archived, or restore them without losing tasks. Archived project pages are read-only, but task filtering remains available. Each project row summarizes completed tasks out of all tasks.

Project search and Search projects apply a name substring query alongside the Active/Archived filter. Task search and Search tasks apply a title substring query alongside completion, priority, and due-range filters. Searches trim surrounding query whitespace, ignore ASCII letter case, and treat each run of ASCII spaces and horizontal tabs in both queries and names/titles as one space. Other internal whitespace and non-ASCII case remain significant. Normalization is only for matching; saved names and titles keep their original spacing and case. Blank queries match everything allowed by the other filters. Queries are page-local, reset when opening a page, and never modify saved data or summaries. Changing filters and editing, creating, or moving tasks retains the applied task query and immediately re-evaluates membership. Search stays usable in archived projects.

Every project page provides Download project, including archived and empty projects. It downloads UTF-8 `workboard-project.json` with format `workboard-project`, version `1`, and a project object containing name, archived, defaultPriority, and tasks. All live and deleted tasks are included in stored order, regardless of page filters, with title, completed, priority, dueDate, notes, and deleted fields. Notes line endings are represented as LF; stored notes remain unchanged. The read-only export excludes IDs and remembered movement positions, does not include other projects' tasks, and leaves all data and page controls unchanged. The download endpoint is `GET /api/projects/<id>/export`.

The home page provides Project JSON, Imported project name, and Import project. Paste a version-1 portable document and supply a nonblank name override. Import validates every required field and calendar date before writing anything, then atomically creates and opens an independent project. The override is trimmed; supplied task titles retain their exact text. Notes use LF line endings. Archive state, project default, task fields, deletion status, and supplied task order are preserved, with fresh IDs and remembered positions. Additional properties cannot set internal identities. Invalid documents show `Invalid project JSON`; a blank override shows `Project name is required`. Rejections retain both inputs and leave all existing data unchanged. The endpoint is `POST /api/projects/import` with `{ "name": "Copy name", "projectJson": "<portable JSON text>" }`.

Task directory on the home page opens `/directory`, a read-only view across projects. Each opening defaults to Active project scope, All live tasks, All priorities, and empty due range and Directory search. Scope, completion/deletion, priority, inclusive due range, and normalized title search intersect without changing saved data. Invalid directory range submissions show an alert and restore both textboxes to the last applied boundaries, leaving all other filters and results unchanged. Results follow project creation order and each project's reserved task order, showing exact titles, owner names, completion, priority, due dates, and plain-text multiline notes. Notes and owner names do not add search matches. Deleted and archived tasks remain readable; rows offer only Open project, which starts the owner's ordinary default project filters. Projects returns home with its usual empty search. `GET /api/directory` supplies current task fields and owner metadata, including deleted tasks, using the existing defaults for upgraded records; it has no write interface.

`GET /health` returns `{"status":"ok"}`.

Run automated tests (HTTP/SQLite integration including restart persistence, and browser-controller tests using a minimal DOM adapter):

```sh
npm test
```
