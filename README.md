# Workboard

Requires Node.js 22.22.1. No external dependencies or installation step.

## Run

```sh
PORT=8080 DB_PATH=./data/workboard.sqlite npm start
```

Open `http://localhost:8080`. The server binds to `0.0.0.0`; `PORT` defaults to 8080 and `DB_PATH` defaults to `./data/workboard.sqlite`. Keep the configured SQLite file to preserve projects, archive state, tasks, and completion state across restarts. Existing databases are automatically upgraded with active projects, Normal task priorities, and Normal project defaults, and empty task due dates without changing existing task data. Its parent directory is created automatically.

`GET /health` returns HTTP 200 with `{"status":"ok"}`.

The application uses server-rendered HTML and native forms. SQLite assigns an internal sequence for stable project ordering and remembers each task's position separately in every project it has belonged to. Existing task order is migrated without changes. First-time arrivals and newly created tasks append after all established positions, including positions of tasks currently elsewhere; returning tasks reuse their remembered positions. Task creation and movement save ownership and ordering atomically. Public IDs are UUIDs and never change on a move. Project names and task titles are trimmed before saving and escaped when rendered. Active project pages provide a New project name field and Rename project button. Renaming preserves the URL, creation order, tasks, completion state, and summaries; blank names are rejected. Each project page supports task creation, saved completion checkboxes, and All, Open, and Completed filters. Each task row provides a New task title field and Rename task button. Task renaming trims and validates the title, updates the completion label, and preserves ownership, order, completion, and summaries. Each task provides a Task due date textbox and Save due date button. Empty or whitespace-only values clear the date; other values are trimmed and must be real Gregorian days in YYYY-MM-DD format with years 0001–9999. Dates are saved as calendar-day strings without timezone conversion; invalid values leave the saved date unchanged. Date edits preserve all other task data and both filters. Each task also has an independently saved Task priority selector with Low, Normal, and High options. Each project has a saved Default task priority selector with the same options, initially Normal. New tasks inherit their project's current default; changing a default never changes existing tasks. Defaults remain independent between projects and survive renaming, archival, restoration, and restarts without resetting either task filter. Each project page also provides a Priority filter with All, Low, Normal, and High options. Completion and priority filters combine, retaining creation order and both selections during task edits. Opening a project starts with both filters set to All. Priority and completion edits immediately re-evaluate matching rows; summaries always count all tasks. Each project page also provides Due from and Due through textboxes and an Apply due range button. Applied boundaries are inclusive and intersect the completion and priority filters. A blank boundary is unbounded; undated tasks match only when both boundaries are blank. Boundaries use the same Gregorian validation as task dates; invalid or reversed ranges show an alert and preserve the previous applied range and membership. All edits retain the applied range, and date, priority, or completion edits immediately re-evaluate matching rows. Opening a project from the list resets the range to empty. Range controls remain usable when archived. Filter selections and the applied range are carried in the page URL and forms, not saved as task data. The project list defaults to Active, with an Archived filter and archive/restore controls. Project summaries count all completed and total tasks. Archived project pages retain task filtering but disable project and task renaming, task creation, completion changes, priority edits, due-date edits, and default-priority changes, including direct POST requests. Restoring a project preserves its tasks. Each task row provides a Destination project selector listing only other active projects in project creation order, using their current names, and a Move task button. Moving to a new project appends the task; returning to a previous project restores its relative ordering position, even when multiple tasks return in a different order. Moves preserve the current ID, title, completion, priority and due date, and update both summaries. Remembered positions survive project renaming, archival, restoration, and server restarts; returning never restores older task field values. The source page stays open with its filters and applied range retained. Move controls are disabled for archived sources or when no eligible destination exists; direct requests also reject archived, missing, or same-project destinations and tasks not owned by the source. Small browser event handlers submit completion, priority, and filter changes automatically.

## Search

The project list provides `Project search` and `Search projects`; each project page provides `Task search` and `Search tasks`. Applied queries match substrings, trimming surrounding query whitespace and ignoring ASCII letter case. For matching only, runs of ASCII spaces and horizontal tabs in both queries and saved names/titles become one space. Other internal whitespace and non-ASCII characters remain significant. Saved names/titles and their display are never rewritten by search. Blank queries match everything. Project search intersects Active/Archived; task search intersects completion, priority, and the applied due range. Searches preserve ordering and never affect saved data or all-task summaries. Queries are carried in URLs and forms through filter changes, edits, and validation failures. Archived projects still allow searching. Opening a project from the list or returning with `Projects` resets the corresponding query to empty.
