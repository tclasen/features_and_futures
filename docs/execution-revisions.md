# Execution revisions after pilot 008

Historical manifests and observations stay unchanged. Pilot 009 uses twelve fresh hosted builders and the new Workboard v006 four-task workload. It verifies continued development through project renaming while preserving identity, task state, creation order and archived read-only behavior. Test counts are declared in the project and frozen manifest, rather than inferred from a three-task limit.

`native-and-visible-state-v3` gives every failed browser attempt its factual assertion error and failing page's YAML accessibility snapshot. It removes PM test source, stacks, paths and Playwright's generated instruction block. Native tool failures retain their parser error and supplied schemas. All feedback uses the same renderer, including the first rejection; the PM does not select particular builders for implementation advice. Raw diagnostic reports stay preserved. Notification fingerprints ignore request IDs, schemas and page snapshots while retaining assertion differences; notification does not stop or restart a builder.

`harness-return-v2` records native subprocess return before transcript writes, commit-observer shutdown or gateway drain. Attempt execution uses dispatch/start to harness return; cleanup duration is recorded separately. Task time to acceptance includes the entire elapsed interval, including validation, feedback and cleanup. Every in-flight inference is still drained and accounted for. Earlier pilots retain their original boundaries.

Explicit hosted context settings are 272,000 tokens for both harnesses. Codex's automatic-compaction threshold is 255,616. Pi's maximum output is 16,384, compaction reserve is 16,384 and recent retention is 20,000. A separate Codex output cap has not been verified; native Responses behavior remains part of the harness factor. The four reduced-threshold native probes verify metering through compaction and are recorded in [context verification](context-verification.md).

`behavior-and-restart-v2` observes every promoted deployment for at least thirty seconds, with health and read-only persistence/behavior checks at five-second intervals and a final check. Health samples do not silently retry a transient outage away. A detected incident receives one same-revision server-process restart, then the full behavioral observation window must pass before recovery is recorded. A failed recovery halts the cohort with its incident evidence retained. Restarting unchanged code does not add a promotion or count as deployment rework. These bounded windows remain a sandbox surrogate, not proof of production reliability.

The [real isolated PM fixture](../runs/instruction-effects/pilot-008/preflight/stability-1791569164164478000/result.json) kept `/health` healthy while deliberately making its persisted sentinel unavailable. The controller detected the behavior failure, restarted the actual service process and verified recovery after a complete observation window. This induced PM-only incident is excluded from builder DORA outcomes. The earlier failed fixture preparation is retained separately; it failed before sandbox creation because an archive path was relative, and exposed unsafe cleanup of a partially initialized deployment. Paths are now resolved and cleanup checks creation state.

Before dispatch, all eleven declared acceptance/upgrade/restart test counts were checked against pinned Playwright's test lists; row fixtures verify direct/wrapped content, hidden inactive panels and duplicated visible rows. Eighty-five PM checks pass. Native end-to-end adoption still needs pilot 009 evidence; preparation alone does not establish success.
