# Lessons that improve the experiment

The PM must learn from this pilot and every subsequent evaluation through durable records and verified changes. The authoritative append-only journal is [lessons/records.jsonl](../lessons/records.jsonl); [the index](../lessons/README.md) helps navigation. These are PM-only materials and never enter builder contexts.

For each lesson record a stable lesson ID, unique record ID, UTC time, affected scope, observation, evidence, confidence/root cause, prevention or correction, verification and status, and effects on comparability. Statuses include observed, prepared, adopted, verified and superseded. Append follow-up records with the same lesson ID and a supersedes reference where appropriate. Preserve the original observation. Unknown causes remain hypotheses until checked.

Before preparing a run, review relevant lessons and record adopted safeguards, their exact revisions, checks and deferred items in that run's decisions/lessons-applied.md. At each task checkpoint and after infrastructure/provider incidents, review outstanding lessons and add new evidence. Apply safe PM infrastructure fixes with explicit events and checks. Freeze changes to workload, diagnostics, budgets, accounting, instruction treatments or analysis in a new experimental revision when they alter the comparison.

A lesson must lead to a concrete control when practical: a meaningful regression check, fixture, readiness gate, isolation probe, recovery procedure or preregistered analysis rule. Record verification against raw evidence. Never manufacture a success to close a lesson, claim a cause from one model failure, or mistake a three-task pilot for a maintainability finding.

The user grants full pilot-completion and secret-free publication authority. Preserve timing, token exposure, failure evidence and original Git histories while improving the PM control plane. Publish only after scanning current files, decoded archives and reachable historical objects.
