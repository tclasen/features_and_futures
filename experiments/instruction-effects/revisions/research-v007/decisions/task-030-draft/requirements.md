## Requirement030: atomically import an exported workspace as fresh independent projects

Dependencies: all requirements through029 remain cumulative. On Projects, add a textarea named `Workspace JSON` and a button `Import workspace`. Accept a JSON object with format `workboard-workspace`, integer version1 and a projects array. Validate every project and task before creating any object, using the existing project-export field types, real dates, priority values and task-notes limit. Names and titles must be nonblank after trimming; create trimmed names/titles, preserve completion, priority, due date, deletion and normalized-LF literal notes. A valid empty projects array creates nothing.

Create all imported projects as fresh independent identities appended in input order; preserve their archived/defaultPriority fields and each supplied task order. Equal names within the import or with existing projects are allowed and remain separate owners. Ignore supplied runtime IDs and unknown extra properties. Never merge, overwrite or move existing projects/tasks. Imported deleted tasks keep reserved positions for later restoration; fresh imported ownership begins with the supplied order. On success return to Projects with Active scope and blank project search; imported archived projects are available in Archived scope.

Malformed JSON, an unsupported format/version or any invalid object, including one at the end, announces `Invalid workspace JSON`. No project/task is created or changed, and rejected input stays available. Imported work participates in directory filters, ordering, owner/global summaries, every bulk action, exports and later moves under prior requirements. Imported and pre-existing state survives reload and actual process restart. Earlier single-project import remains cumulative.
