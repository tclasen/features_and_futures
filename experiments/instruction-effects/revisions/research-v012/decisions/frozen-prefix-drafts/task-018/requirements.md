## Requirement018: atomic validated project JSON import

Dependencies: all requirements through017 remain cumulative. The home page provides a multiline `Project JSON` textbox, an `Imported project name` textbox and an `Import project` button. A successful import creates a new independent project named by the trimmed nonblank override textbox, using the version1 portable document defined in017, and opens that new project's detail page. Never overwrite or merge any existing project, task, identity or remembered return position.

Validate the complete document before changing application data. Require the exact format `workboard-project`, numeric integer version1, a project object, a nonblank string project name, Boolean archived flag, defaultPriority exactly Low/Normal/High, and a tasks array. Every task requires a nonblank string title, Boolean completed, priority exactly Low/Normal/High, valid YYYY-MM-DD dueDate or the empty string, string notes, and Boolean deleted. Reject malformed JSON, missing fields, wrong types, unsupported format/version, invalid dates including non-leap February29, and blank task titles. Additional properties do not replace the required fields and must not set internal application identities. An empty tasks array is valid.

A rejected import displays the accessible alert `Invalid project JSON`, retains the submitted JSON and override name, and leaves every project and task unchanged. A blank override instead displays `Project name is required` with the same atomic no-change behavior. Validation remains all-or-nothing when a later task in an otherwise valid document is invalid.

Successful imports preserve supplied task order, exact nonblank title strings, completion, explicit priority, valid due dates, literal notes with LF line endings, and deletion status; retain the imported archived flag and project default. Imported deleted tasks are excluded from live summaries/lists and remain read-only until restored in an active project. Archived imports retain existing read-only behavior. Original projects remain independent when an imported copy is edited or restored. Imported fields and live/deleted order survive reload and server restart, and later moves/returns use the existing position rules within the new project.
